# Platform: Kubernetes Namespace Self-Service

This repo runs a self-service namespace provisioning platform on k3s.
Teams order a namespace (with optional MinIO bucket and PostgreSQL) through
a Backstage template **or** by dispatching a task to Claude.

Stack: k3s · Argo Events · Argo Workflows · Kyverno · MinIO · Backstage

---

## Prerequisites before dispatching

1. **k3s is running** — `kubectl get nodes` shows a Ready node.
2. **Argo Events webhook is reachable** on port 12000:
   ```bash
   kubectl -n argo-events port-forward svc/backstage-webhook-eventsource-svc 12000:12000 &
   ```
3. *(Optional)* Argo Workflows UI on port 2746:
   ```bash
   kubectl -n argo port-forward svc/argo-server 2746:2746 &
   # → https://localhost:2746
   ```
4. *(Optional)* MinIO console on port 9001:
   ```bash
   kubectl -n minio port-forward svc/minio-console 9001:9001 &
   # → http://localhost:9001  (admin / changeme123)
   ```

## Provision a namespace

### Via helper script (preferred)
```bash
bash scripts/provision-namespace.sh <namespace> <team> <cpu> <memGi> <minio> <postgres>
```

| Arg | Type | Example | Description |
|-----|------|---------|-------------|
| namespace | string | `team-alpha` | RFC 1123, lowercase, hyphens only |
| team | string | `alpha` | RBAC Group name |
| cpu | integer | `2` | CPU cores limit (> 4 triggers approval) |
| memGi | integer | `4` | Memory limit in Gi (> 8 triggers approval) |
| minio | bool | `true` | Create a MinIO bucket |
| postgres | bool | `false` | Deploy a PostgreSQL StatefulSet |

**Examples:**
```bash
# Small request — auto-approved
bash scripts/provision-namespace.sh team-alpha alpha 2 4 false true

# Large request — will require operator approval
bash scripts/provision-namespace.sh team-ml ml 8 32 true true
```

### Via curl directly
```bash
curl -s -X POST http://localhost:12000/namespace-request \
  -H 'Content-Type: application/json' \
  -d '{
    "namespace":      "team-alpha",
    "team":           "alpha",
    "cpuLimit":       "2",
    "memoryLimit":    "4Gi",
    "requestMinio":   false,
    "requestPostgres": true
  }'
```

**Field reference:**
- `cpuLimit` — string, plain integer cores, e.g. `"2"`, `"4"`, `"16"`
- `memoryLimit` — string, Gi suffix, e.g. `"4Gi"`, `"8Gi"`, `"32Gi"`
- `requestMinio` / `requestPostgres` — JSON boolean (`true` / `false`)

## Resource policy thresholds (Kyverno-enforced)

| Resource | Auto-approved | Requires manual approval |
|----------|--------------|--------------------------|
| CPU | ≤ 4 cores | > 4 cores |
| Memory | ≤ 8 Gi | > 8 Gi |

When a request exceeds a threshold:
1. The Argo Workflow tries to apply the ResourceQuota → **Kyverno blocks it**
2. The workflow pauses at the `suspend-for-approval` step
3. An operator must **resume** the workflow (see below)
4. The workflow re-applies the quota with the `provisioning.io/approved: "true"` annotation

## Check workflow status

```bash
# List all provisioning workflows
kubectl get workflows -n argo

# Detailed view with status
argo list -n argo

# Watch a specific workflow
argo get <workflow-name> -n argo --watch

# Tail workflow logs
argo logs <workflow-name> -n argo
```

A workflow stuck at `Running` with a `suspend-for-approval` step needs operator review.

---

## Approve a suspended workflow

```bash
# List workflows pending approval (status = Running, step = suspend-for-approval)
argo list -n argo | grep Running

# Resume after reviewing the request
argo resume <workflow-name> -n argo
```

After resuming, the workflow applies the ResourceQuota with the approval annotation
and continues to provision RBAC, MinIO bucket (if requested), and PostgreSQL (if requested).

## Verify a provisioned namespace

```bash
# Namespace exists with correct labels
kubectl get ns <namespace> --show-labels

# ResourceQuota applied
kubectl describe resourcequota team-quota -n <namespace>

# RBAC in place
kubectl get role,rolebinding -n <namespace>

# LimitRange + NetworkPolicies (generated by Kyverno)
kubectl get limitrange,networkpolicy -n <namespace>

# PostgreSQL running (if requested)
kubectl get statefulset,pod,svc -n <namespace>

# MinIO bucket exists (if requested)
kubectl -n minio exec deploy/minio -- \
  mc alias set local http://localhost:9000 admin changeme123 2>/dev/null && \
  mc ls local/ | grep <namespace>
```

## Example dispatch phrases

When dispatching to Claude, you can use natural language:

| Phrase | What Claude will do |
|--------|---------------------|
| "Provision namespace `team-alpha` for team `alpha`, 2 CPU, 4Gi, with postgres" | Calls script with those params |
| "Give team `ml` a namespace with 16 CPU and 64Gi, MinIO and postgres" | Calls script; workflow will suspend for approval |
| "Check if any namespaces are waiting for approval" | Runs `argo list -n argo \| grep Running` |
| "Approve the pending provisioning workflow" | Lists suspended workflows, resumes the right one |
| "Show me what's in the team-alpha namespace" | Runs the verify commands above |
| "Is team-alpha's postgres running?" | Checks StatefulSet status in that namespace |

## Install the full stack from scratch

```bash
chmod +x k8s/install.sh
sudo k8s/install.sh
```

This installs k3s, Argo Workflows, Argo Events, Kyverno, MinIO, and applies all manifests.
